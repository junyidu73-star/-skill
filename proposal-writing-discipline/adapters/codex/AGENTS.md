# AGENTS.md

撰写、修改或审查申报书、项目方案、研究计划等正式文案时，按下面这份纪律执行。规则对每一段都生效，不许只用在其中一部分，全文写完必须做终审并输出终审报告。

开工前先建立四份底稿，并在整个任务中持续维护：

- 本意清单：必须保留的事实、数字、姓名、术语、方法名、时间节点。
- 脉络表：全文一句话主张，每一节要回答的问题，每一段的中心句。
- 术语表：同一概念只用一个名字，首次出现时解释一次。
- 引用台账：格式见下文第六部分。

下面是从 SKILL.md 同步的规则正文，修改时请改 SKILL.md，然后运行 scripts/sync-adapters.ps1。

---

# 一、使用方式（强制，全程适用）

1. 本技能适用于整篇文案的每一段，不允许只在部分段落使用。
2. 开始前先建立四份底稿，并在整个任务中持续维护：
   - 本意清单：必须保留的事实、数字、姓名、术语、方法名、时间节点。
   - 脉络表：全文一句话主张，每一节要回答的问题，每一段的中心句。
   - 术语表：同一概念只用一个名字，首次出现时解释一次。
   - 引用台账：见第六部分。
3. 每写完一节，立即用第八部分的快速自查清单检查一遍，通过后再写下一节。
4. 全文完成后，必须执行第九部分的整篇终审，并输出终审报告。
5. 如果发现前面某段没有按本技能写，要回头补做，不得带着问题继续。

# 二、把握分寸

优先级从高到低：事实与本意，因果成立，整体结构，文风。

- 不得改动数据、姓名、数字、专业术语、方法名和申报体例要求的固定用语。
- 申报书允许书面语，也允许“拟”“将”“本项目”这类用法，不要为了口语化破坏严谨。
- 原文通顺且逻辑成立的句子不改。只改确实影响理解、显得机械或逻辑不成立的地方。
- 修改后如果意思发生变化，立即回退，改为向作者提问。
- 问题分三级：必改（事实错误、因果不成立、前后矛盾、引用不支撑）；建议改（翻译腔、冗长、重复）；可保留（体例允许、专业必需、作者风格）。只处理前两级。
- 不得把全文改写成另一篇文章，也不得为了规避某种写法而削弱必要的表达。

# 三、文风自然度（解决生硬与翻译腔）

常见成因，写作时要主动避免：

1. 先按英文思路构思，再逐词转成中文，导致名词化堆叠和被动句。
2. 概念词直译后没有消化，保持着英文的语序。
3. 模型惯用模板，如总分总、整齐的排比、口号式对仗。
4. 把因果关系压成名词短语，丢掉朴素的连接词。
5. 抽象名词代替具体动作，一句话塞进多个动作。

处理办法：

- 动词还原。“进行分析”写成“分析”，“实现提升”写成“提高”，“开展验证”写成“验证”。
- 主语明确，优先主动句，少用“被……所”“由……加以”。
- 一句一个主要意思，单句一般不超过 70 字，嵌套超过两层就拆开。
- 用“因此、但是、所以、同时、另一方面”等朴素连接词表达关系，不用名词短语硬压。
- 少用“通过……来……”，改成“用……”。多重“基于……的……的……”要拆句。
- 避免空洞套词：旨在、致力于、赋能、闭环、贯通、抓手、范式、全链条、深度融合、有机统一。需要表达的意思用具体描述替代。
- 避免口号式对仗，如“是……而不是……”“既……又……又……”连用。
- 专业术语保留，首次出现解释一次，此后保持同名。
- 读一遍：如果一句话需要回头重读才能懂，就重写。

# 四、因果与关联（解决强行绑定）

凡是带关系的表述（因此、从而、使得、以便、为了、对应、由此、据此、进而），逐句做三项检查：

1. A 是不是 B 的真实原因、手段或依据？去掉 A，B 还成立吗？如果成立，两者是并列关系，不是因果，改用“同时、另外”，或者拆成两句。
2. 中间是否缺少第三个因素或一步推理？缺了就补，补不出来就降级为“拟检验”“可能”。
3. 结论的强度是否超过证据？已完成与拟完成要分清，“拟做”不能写成“已证明”。

常见的强行绑定，要主动识别并拆开：

- 工具或数据存在，就被写成结论成立。
- 引用了一篇相关文献，就被当作支撑整个论点。
- 两个互相独立的指标被合在一个“因此”里。
- 时间先后被写成因果。
- 方法与目的错配，一个方法被说成解决它实际不涉及的问题。

每个方法都要有对应目的，每个目的都要有对应方法，每个结论都要有依据，并在终审时列出对照表。

# 五、整篇结构（解决上下文逻辑混乱）

1. 动笔前先写脉络表。全文只有一个中心主张，每一节只回答一个问题，每一段只有一个中心句。
2. 推荐顺序：背景，缺口，目标，方法，验证，预期。同一个内容只在一处详述，其他地方写“见某节”，不重复展开。
3. 数字、编号、人数、n 值、阶段时间，一处定义，他处必须一致。
4. 前一节的结论要能自然引出后一节，每节开头一句交代它与上文的关系。
5. 不得出现“前面说 A，后面突然讲 B”的跳跃。必须转换主题时，用一句话说明为什么转。
6. 术语、对象、分档名称、变量名全文统一，不得换说法。

# 六、参考文献（解决没读透、强行关联）

流程：

1. 先列“待支撑论断清单”，每个需要引用的论断占一行。没有论断就不引用。
2. 检索候选文献，并判断可读性：
   - 开放获取全文（PMC、arXiv、bioRxiv、出版社开放版）：必须读全文相关部分。
   - 有付费墙、只能读摘要：在台账里标“仅摘要”，只引用摘要里明确写出的内容。
   - 读不到：不引用，或标【待核实】。
3. 阅读深度：摘要不足以引用。引用前必须读到支撑论断的那一节（方法、结果或讨论），并记录位置（章节、图表或页码）。将作为方法依据的核心文献通读全文。
4. 维护引用台账，每条包含：论断，文献，是否读过全文，支撑位置，支撑强度（直接、部分、背景），该文与本项目相关的具体部分。
5. 只有一小部分内容与本项目相关时，只引用那一部分，并在正文里写出限定条件（对象、条件、结论范围）。不能限定就不引用，不得扩大到整篇文献。
6. 禁止：凭记忆填写作者、年份、卷期页码、DOI；为凑数量而引用；用综述代替一手来源去支撑具体数据；引用方向与论断相反或无关的文献。
7. 引完后自检：论断有没有超出文献原话？数字、条件、对象是否一致？
8. 编号按正文首次出现顺序，正文引用号与参考文献列表必须一一对应，列表中没有未被引用的条目。

# 七、格式习惯（避免一眼看出是模型生成）

- 少用引号。只用于专有名称、首次定义的术语和直接引语，不用来强调或表示“所谓”。
- 少用冒号。小标题、编号条目标题、时间和比值等规范场合除外。不要用“核心：”“总结：”这类引出，改用句子自然衔接。
- 不用反问句和设问句，整篇为零。
- 少用破折号、加粗强调、表情符号。
- 不用“值得注意的是”“需要指出的是”“综上所述”“总而言之”等套话。
- 避免三段排比和每段都是同一种总分结构。段落长短要有变化。
- 申报书的章节编号和条目体例可以保留，但每个条目写成完整的句子，不要全是名词短语的堆叠。
- 同一节里可以段落与条目混用，不要所有章节套同一个模板。

# 八、每节快速自查清单

写完每一节后逐条确认：

1. 这一节只回答一个问题吗？与上一节如何衔接？
2. 每个带关系的句子，通过第四部分的三项检查了吗？
3. 数字和术语与本意清单、术语表一致吗？
4. 有翻译腔、套话、口号式句子吗？
5. 有引号滥用、冒号滥用、反问吗？
6. 新增的引用，台账登记了吗，有没有超出原文所说？

# 九、整篇终审（全文完成后必须执行）

按四遍通读，每一遍都要写出结果：

1. 因果遍：列出所有带关系的句子，逐条给出“成立、降级、拆开、删除”的处理。同时列出方法与目的、结论与依据的对照表。
2. 结构遍：对照脉络表，检查有无跳跃、重复、前后矛盾，以及数字和术语是否统一。
3. 文风遍：检查翻译腔、套话、引号、冒号、反问，并确认没有为了改文风而改变本意。
4. 引用遍：核对台账，确认每个引用都有全文或明确标注的摘要依据，论断没有超出文献，编号与列表一一对应。

最后做分寸检查：对照本意清单，确认事实、数字、术语、方法没有被改动，申报体例没有被破坏。

输出终审报告，包括：已修改项（位置、原文、修改后、理由），待作者决定项（给出两个备选写法），无法验证项（标【待核实】），以及确认保留的问题和保留理由。
